一、文件系统结构（根目录 / ）
------------------------------------------------------------
/bin        : 基础命令程序（ls, cp, mv, cat 等）
/boot       : 启动引导文件，不要乱动
/dev        : 设备文件（硬盘、键盘等都以文件形式存在）
/etc        : ★ 系统配置目录，几乎所有服务的配置文件都在这里
              例：MySQL 配置 → /etc/mysql/mysql.conf.d/mysqld.cnf
/home       : 普通用户的家目录
/root       : ★ 超级管理员(root)的家目录，登录后默认位置
              例：你上传的 ai-slim.tar 镜像包就在 /root 下
/var        : ★ 动态数据目录，存放日志、数据库文件、Docker 数据
              例：日志 → /var/log
                  MySQL 数据 → /var/lib/mysql
/var/log    : ★★★ 日志目录，排查问题的第一站
              例：系统日志 /var/log/syslog
/tmp        : 临时文件目录，重启后通常清空
/usr        : 用户安装的软件目录
/opt        : 手动安装的第三方软件目录
/proc       : 虚拟文件系统，存放进程和系统信息
/run        : 运行时数据，重启后清空


二、常用文件操作命令
------------------------------------------------------------
ls          : 列出目录内容
    ls -l   : 详细列表（看权限、大小、修改时间）
    ls -a   : 显示隐藏文件（以 . 开头的文件）

cd          : 切换目录
    cd ~    : 回到当前用户的家目录
    cd /    : 回到根目录
    cd ..   : 回到上一级目录

pwd         : 显示当前所在的完整路径

cat         : 查看文件全部内容（适合小文件）
head -20    : 查看文件前 20 行
tail -20    : 查看文件最后 20 行
tail -f     : ★ 实时追踪文件尾部（日志动态刷新）
              按 Ctrl+C 退出

grep        : ★ 文本搜索过滤，日志排查核心命令
    用法：grep "关键词" 文件名
    例：grep "错误" server.log           → 搜包含"错误"的行
         grep -i "error" app.log         → 忽略大小写搜 error
         grep -E "错误|失败|超时" log    → 同时搜多个关键词
         grep -n "ERROR" log             → 显示匹配行的行号
         grep -A 3 "ERROR" log           → 显示匹配行及其后 3 行

cp          : 复制文件
    例：cp 源文件 目标文件
        cp config.yml config.yml.bak     → 备份配置文件

mv          : 移动文件 / 重命名文件
    例：mv 旧名 新名                     → 重命名
        mv server.log api.log            → 改名

rm          : 删除文件（慎用！不可逆）
    rm -r   : 递归删除目录及其中所有文件

echo        : 输出文本，或写入文件
    echo "内容" > 文件                   → 覆盖写入
    echo "内容" >> 文件                  → 追加写入

touch       : 创建空文件


三、文件权限（ls -l 输出解读）
------------------------------------------------------------
输出示例：-rw-r--r-- 1 root root 74 May 20 15:22 api.log

第一部分：文件类型和权限（-rw-r--r--）
    -       : 普通文件（d = 目录）
    rw-     : 所有者(root)权限 → 可读(r) 可写(w) 不可执行(-)
    r--     : 同组用户权限   → 只读
    r--     : 其他用户权限   → 只读

第二部分：1          → 硬链接数
第三部分：root       → 文件所有者
第四部分：root       → 所属用户组
第五部分：74         → 文件大小(字节)
第六部分：May 20...  → 最后修改时间
第七部分：api.log    → 文件名

权限数字表示（部署时经常遇到）：
    r = 4, w = 2, x = 1
    rw- = 6
    r-- = 4
    常见：644 → 所有者可读写，其他人只读
          755 → 所有者全权限，其他人读+执行


四、进程管理命令
------------------------------------------------------------
ps aux      : 查看所有运行中的进程
    ps aux | grep 关键词                → 过滤指定进程
    例：ps aux | grep mysql              → 找 MySQL 进程
        ps aux | grep docker             → 找 Docker 进程

top         : ★ 实时任务管理器，动态显示 CPU 和内存占用
    按 q 退出

kill        : 终止进程（按 PID）
    kill 12345                          → 优雅终止
    kill -9 12345                       → 强制杀死（可能导致数据丢失）

systemctl   : ★ 管理系统服务
    systemctl status 服务名              → 查看服务状态
    systemctl start 服务名               → 启动服务
    systemctl stop 服务名                → 停止服务
    systemctl restart 服务名             → 重启服务
    systemctl enable 服务名              → 开机自启

netstat     : 查看网络端口监听
    netstat -tlnp | grep 3306           → 看 MySQL 是否在监听


五、日志查看与排查
------------------------------------------------------------
1. 容器日志
   docker logs 容器名                    → 查看容器日志
   docker logs 容器名 --tail 30          → 最后 30 行
   docker logs -f 容器名                 → 实时追踪容器日志

2. 系统日志
   /var/log/syslog                       → 系统全局日志
   /var/log/auth.log                     → 登录认证日志
   /var/log/mysql/error.log              → MySQL 错误日志

3. 日志排查黄金三步法
   ① tail -100 /var/log/xxx.log         → 先看最近 100 行，了解全貌
   ② grep "ERROR\|FATAL\|FAIL" 日志文件  → 用 grep 过滤关键错误
   ③ tail -f 日志文件                    → 实时监控，复现问题时观察

4. 经验教训
   - 任何服务出问题，先看日志，不要猜
   - docker logs 是排查容器问题的最快路径
   - grep 能从几万行日志里瞬间定位关键信息
   - 养成打日志的习惯，将来排查省百倍时间
